## Подтверждённые сильные стороны

Использовать в резюме и письмах с примерами:

1. **Linux (Debian/Ubuntu)** — администрирование, сервисы, диагностика.
2. **Сети** — VLAN, VPN, failover (OpenWRT/mwan), MikroTik, маршрутизация.
3. **Proxmox VE** — упоминается в текущей работе (Кузминки).
4. **Веб-стек** — Nginx/Apache, MySQL, PostgreSQL (частично).
5. **Мониторинг** — Zabbix на критичных серверах.
6. **Автоматизация** — Python, скрипты, Git/GitHub.
7. **Эксплуатация 24/7** — розница/производство, реальные инциденты.

## Приоритеты прокачки

### P0 — ближайшие 4–6 недель (максимум отдачи на отклики)

| # | Цель | Артефакт «готово» | Критерий |
|---|------|-------------------|----------|
| 1 | **GitLab CI** | Репо на GitHub/GitLab: build → test → deploy Docker | README + `.gitlab-ci.yml`, можно demo app |
| 2 | **Упаковка резюме** | Опубликованное DevOps-резюме на hh | Нет «руководитель» в title; ключевые слова из 3 JD |
| 3 | **Ceph + Proxmox** | Homelab: 3 VM или nested, Ceph OSD + одна VM с диском из Ceph | Скрин/док в GitHub: `docs/proxmox-ceph-lab.md` |
| 4 | **Честная самопроверка** | Заполнить все `❓` в `resume.md` | Только правда в резюме |

### P1 — 6–10 недель

| # | Цель | Артефакт |
|---|------|----------|
| 5 | **Ansible** | Playbook: nginx + docker + deploy |
| 6 | **Terraform** | Модуль: VM в Proxmox или cloud |
| 7 | **Prometheus + Grafana** | Мониторинг demo-стека, алерт в Telegram |
| 8 | **Kubernetes (k3s)** | Деплой приложения + Ingress + persistent volume |

### P2 — по целевым вакансиям (веб / agency / proptech)

- CDN + nginx cache strategy (документ с диаграммой).
- ClickHouse + MinIO в docker-compose.
- Redis для кеширования сессий/страниц.

### P3 — позже

- GitOps, CKA, углублённый AWS/Yandex.
- Английский B1.
